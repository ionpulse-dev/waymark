# Knowledge base repository

## Technical Goal

Define the content repository of a knowledge base: its layout, its shared settings file, and its rules file for agents. One knowledge base is one Git repository, whoever owns it: a company, a team, or one person.

## Dependents

- `create-knowledge-base` and `join-knowledge-base` — create or clone this layout.
- `project-binding` — the UUID in `waymark.toml` identifies the knowledge base.
- `plain-git-access` — the `AGENTS.md` in the repository root carries the plain-Git rules.

## Deliverables

- The layout of a content repository.
- The schema of `waymark.toml`.
- The templates for `waymark.toml` and `AGENTS.md`.
- The Obsidian vault settings and Git ignore rules that `init` writes.

## Scope

**In scope:**
- Files in the repository root and the `knowledge/` tree.
- Teams as folders, and the optional `_team.md` convention.
- Shared settings. Personal settings are specified in `join-knowledge-base`.

**Out of scope:**
- The format of one document (see `document-format`).
- The tooling repository. The content lives in a separate repository per knowledge base.

## Constraints

- The Git remote is private and belongs to the owner of the knowledge base.
- Everyone with read access to the repository sees every document. Git has no read permission per folder. One repository has one audience.
- The repository holds no secrets and no personal settings.

### Layout

```text
<slug>-knowledge-base/        (cloned to ~/Projects/<slug>-knowledge-base by default)
  waymark.toml                shared settings
  AGENTS.md                   rules for agents
  .obsidian/app.json          Markdown links and relative paths as defaults
  .gitignore                  .obsidian/workspace*.json, .obsidian/cache, .waymark/
  .waymark/                   lock and state, never committed
  knowledge/
    backend/
      payments/
        idempotency-keys.md
```

- `.waymark/` in the content repository holds the lock and the sync state. It is a dot folder, so Obsidian ignores it, and Git ignores it too. In a project folder, `.waymark/` is the binding and is committed (see `project-binding`). A session that starts inside the content repository has no binding and uses that repository directly.
- `waymark.toml` and `AGENTS.md` are allowed in the vault root.
- **The folder is the owner.** A document in `backend/payments/` belongs to that team. A parent folder includes its children.
- **The organization builds the tree.** waymark has no built-in folders. A knowledge base can add a `shared/` folder or a `_team.md` document (type `team`) per folder with contacts. These are normal documents.
- **No `owners` field.** The author is in Git history, with name and email.
- **The document type is in the frontmatter, not in the folder.**
- Folders are teams. Reorganizations use `move-documents`.

### `waymark.toml` (shared settings)

```toml
name = "Example Company"        # asked by init
id = "<uuid>"                   # generated by init, identifies the knowledge base
slug = "example"                # default folder ~/Projects/example-knowledge-base
tools = ["claude-code", "codex", "copilot"]
types = ["fact", "decision", "contract", "howto", "glossary", "team", "gotcha"]
verification = false            # true: owners verify documents

[trust]
stale_after_days = 180

[read]
default = "manual"              # start value for a person: auto | manual
max = "auto"                    # loosest value allowed

[write]
default = "manual"              # auto | confirm | manual
max = "auto"
confirm_in = "chat"             # chat | app
confirm_in_min = "chat"         # weakest value allowed

[people]
email_domains = []              # optional allowed author domains
email_blocklist = []            # extra blocked parts

[documents]
max_bytes = 102400
title_max_words = 15
description_max_words = 50

[search]
max_results = 5
max_tokens = 800

[lint]
extra_secret_patterns = []      # regular expressions
```

## Acceptance Criteria

- **Given** a new repository from `init`, **When** it is opened in Obsidian, **Then** it opens as a vault and new links use Markdown links with relative paths.
- **Given** a repository, **When** `git status` runs after Obsidian was used, **Then** personal Obsidian files and `.waymark/` do not show as changes.
- **Given** a `waymark.toml` without `id`, **When** a command reads it, **Then** the command fails with a setup problem.
- **Given** a value outside the allowed limits in a person's settings, **When** the CLI reads both, **Then** the stricter value applies.
- **Given** a folder reorganization, **When** it is done through waymark, **Then** no `owners` field or team list needs an update.
