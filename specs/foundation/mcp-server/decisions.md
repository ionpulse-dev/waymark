# Decisions: MCP server

_The decisions that led to the MCP-only design are in `docs/architecture-direction.md` and `docs/decisions.md`._

## `rmcp` and `tokio` — 2026-11-14

**Decision:** The server uses `rmcp` 3.10.0 (released 2026-11-12, 49 million downloads) with `tokio`. All `rmcp` code stays in `src/mcp/mod.rs`.

**Alternatives considered:** A hand-written JSON-RPC server (rejected: more code to maintain, and the protocol changes). Another MCP crate (none with this adoption).

**Reason:** It is the official Rust SDK and the most used. A thin wrapper keeps a later change cheap. Decided autonomously. Source: crates.io on 2026-11-14.

## Hand-written tool schemas — 2026-11-14

**Decision:** Input schemas are written with `serde_json::json!`, not generated by `schemars`.

**Alternatives considered:** Derived schemas (rejected: they add long descriptions and fields that cost context in every session).

**Reason:** The tool descriptions are the only built-in guidance and must stay short. Decided autonomously.

## Two more error codes — 2026-11-14

**Decision:** The codes `not_found` and `invalid_arguments` are added to the list of the requirements.

**Reason:** Features need to tell "no such document" and "wrong call" from `validation_failed`, which is for content checks. Decided autonomously.

## The `settings` field is in every result — 2026-11-14

**Decision:** Every result, also an error, carries `settings` (the effective limits) and `notices` when there are any.

**Reason:** This follows the requirements. An agent can then see why a tool is missing. Decided autonomously.

## Context budget for `tools/list` — 2026-11-14

**Decision:** The tool descriptions together stay under 6000 characters, and the whole `tools/list` result under 20000. A test fails above that.

**Reason:** The schemas use context in every session. The numbers are a first guess and can change after dogfooding. Decided autonomously.

## stdio logs go to stderr — 2026-11-14

**Decision:** The server writes logs only to stderr. Stdout carries only protocol messages.

**Reason:** A stray line on stdout breaks the protocol.

## One knowledge base per process, found by `--repo` and `--path` — 2026-11-14

**Decision:** The server does not depend on the working folder. `--repo` and `--path` name the knowledge base. If neither is given, the server looks for a knowledge base in the working folder and above it, and in `~/Projects/*-knowledge-base` if exactly one exists (see `project-binding`).

**Reason:** Answers the open question of the original spec. Decided autonomously.
