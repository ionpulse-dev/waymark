# Plan: Document format

_Written alongside `requirements.md`. Describes the technical approach._

## Overview

The `waymark` binary gets one Rust module, `format`, that reads, checks, and writes one document exactly as the MKBase Document Standard says. It has no I/O of its own beyond reading file bytes it is given, so the MCP tools, `lint`, and the tests all call the same code. The standard and its conformance fixtures in `standard/` are the test oracle.

## Components Affected

- `standard/mkbase-1.0.md` — section 9.1 (counting rules) was added first, as the workflow requires. Annex B named a shell checker that does not exist here. The annex now describes the conformance set without a named checker (see `decisions.md`).
- `standard/conformance/` — used as test input. It is not changed. Boundary cases (15 and 16 words, the hard cap) are generated by the tests, and file-name rules are unit tests on strings, so no new fixture files are needed.
- `mcp-server` — calls this module in every read and write tool. It does not define its own format rules.
- `quality-checks` — `lint` calls the checks of this module and adds the checks that need more than one document or Git (duplicate titles, author against Git history, secrets).

## New Files

One crate with a `format` module (see `decisions.md`).

- `src/format/mod.rs` — public API: `parse`, `check`, `render`, and the `Finding` type.
- `src/format/frontmatter.rs` — splits the frontmatter from the body and reads the flat YAML (untyped, with `yaml-rust2`) into a typed `Frontmatter`. Rejects nested values. This is the only file that touches the YAML crate.
- `src/format/fields.rs` — field table: names, types, required or not, order of writing, and the per-field rules (status values, date format, `"Name <email>"`, `disputed` with `dispute_reason`).
- `src/format/id.rs` — document ID from a path, and the file-name rules (lowercase letters, digits, `-`, no forbidden character).
- `src/format/links.rs` — finds relative Markdown links, wikilinks in the body, and wikilinks in properties. Checks that a target exists when a document set is given.
- `src/format/count.rs` — the counting rules of section 9.1: bytes, words, markup removal, estimated tokens.
- `src/format/limits.rs` — the three settings (`documents.title_max_words`, `documents.description_max_words`, `documents.max_bytes`) with the standard defaults.
- `src/format/finding.rs` — `Finding { path, rule, severity, message }`. The `rule` names are stable strings that the conformance fixtures use.
- `tests/format_conformance.rs` — runs every file of `standard/conformance/vault/` (must pass) and `standard/conformance/invalid/` (must fail, with the rule named by the file name).
- `tests/format_counting.rs` — unit tests for the counting rules, including the 15/50-word boundary.
- `Cargo.toml` — minimal package `waymark` with `yaml-rust2`. `mcp-server` extends it later.
- `src/lib.rs` — declares `mod format`. `mcp-server` adds the other modules later.

## Technical Approach

1. **Parse.** Read bytes, check UTF-8 and LF line ends. Split at the two `---` lines. Parse the frontmatter with `yaml-rust2` (see `decisions.md`) into its untyped value tree. Convert it to a flat map. A value that is a map, or a list of non-strings, is a `nested-property` finding.
2. **Check the fields.** Walk the field table. Missing required fields, wrong types, bad dates, `updated` before `created`, a `status` other than `active` or `deprecated`, and `disputed: true` without `dispute_reason` each produce one finding with a fixed rule name. Unknown fields are kept and never rejected, because other tools write their own.
3. **Check names and IDs.** The ID is the path below the root without `.md`. The file-name rule is checked on the last path segment and on each folder name.
4. **Check size and words.** Bytes of the whole file against the hard cap. Words of `title` and `description` against their limits. Limits come from a `Limits` value, so a knowledge base can change them.
5. **Check links.** Without a document set, check only the form (relative Markdown with `.md`, or wikilinks; full-path wikilinks in properties). With a document set, check that each target exists. A missing target is an `error` for a link in a property and a `warning` for a link in the body (see `decisions.md`).
6. **Render.** Write a document with the fields in table order, dates as `YYYY-MM-DD`, LF line ends, and relative Markdown links. `render` never changes the body text it is given, so edits made in Obsidian survive.
7. **Count.** One function per rule of section 9.1. `lint` and the write tools both use them, so they cannot disagree.
8. **Findings are data.** Nothing prints or exits inside the module. The caller decides: a write fails with `validation_failed`, and `lint` lists the findings.

Check order is fixed (parse, fields, names, size, links), and the module returns all findings, not only the first, so a person fixes a document in one pass.

## Dependencies on Other Foundation Items

- `mcp-server` — loads the config that fills `Limits`. Its requirements name `serde` with a YAML crate for frontmatter. That line must be aligned with the decision here (see `todo.md`).
- `knowledge-base-repo` — defines the root (the folder with `.mkbase`) and the `exclude` file. The `format` module takes the root as an input and does not find it.
- `quality-checks` (feature) — consumes the findings. The rule names are the contract between the two.

## Risks

- **Obsidian drift.** Obsidian has no specification. The release check of the sample vault, with the baseline in `decisions.md`, is the only guard. It is manual, and it also verifies the Obsidian 1.4 floor.
- **YAML crate maintenance.** `yaml-rust2` gets only basic maintenance, and its successor is `saphyr`. The crate is used in one file, so a swap is local. Check the release dates on crates.io before the first implementation task.
- **YAML edge cases.** Flat YAML hides traps: unquoted dates, `yes`/`no` as booleans, numbers as titles. The fixtures must cover them, and `parse` must treat a title that YAML reads as a non-string as a type finding.
- **Word counting across languages.** Splitting on white space undercounts text in languages without spaces. The limits are rough guards, so the plan accepts this. The sample vault already has a non-ASCII document.
- **Comment markup.** Rule 3 of section 9.1 removes the text of `%%` comments but only the markers of callouts, embeds, and highlights. An unclosed `%%` runs to the end of the document, as in Obsidian (see `decisions.md`).
- **Round-trip.** `render` after `parse` must not rewrite a document that is already conforming. A test with every vault document checks this.
