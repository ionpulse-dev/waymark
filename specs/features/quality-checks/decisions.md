# Decisions: Quality checks

> **Note 2026-11-11:** All decisions stay valid. `lint` and `index` are tools, and a failed check is `validation_failed`.

_Records why technical choices were made. Never delete entries — add new ones as decisions are made. This file helps future AI sessions and developers understand settled choices without re-debating them._

---

## Checks before every commit — 2026-11-08

**Decision:** The same checks run before every commit and on demand.

**Reason:** Format, size, links, and secrets are the main guard against noise and leaks.

## Generated indexes — 2026-11-06

**Decision:** No central index file that everyone edits. Indexes are generated.

**Reason:** A shared index file would cause merge conflicts.

## Company patterns — 2026-11-06

**Decision:** Secret patterns can be extended in the shared settings.

**Reason:** Some organizations have strict rules, for example banks with IBAN patterns.

## Checks are tools with a `next` sentence — 2026-11-11

**Decision:** A failed check returns a plain reason and a `next` sentence so that the agent can fix the input.

**Reason:** rejections should teach the agent.

## Rules, severities, and rule names — 2026-11-14

**Decision:** The rule names of the format checks are the file names of `standard/conformance/invalid/`. This spec adds `bad-file-name`, `bad-encoding`, `bad-line-ending`, `document-too-large`, `duplicate-title`, `author-mismatch`, `author-not-allowed`, `secret`, `personal-data`, and `index-stale`. `broken-link` is an error in a property and a warning in the body, as `document-format` decided. `author-mismatch` and `index-stale` are warnings. The others are errors.

**Reason:** A warning must never block a manual edit that is correct. Git can differ from the frontmatter for good reasons, such as a rebase. Decided autonomously.

## `lint` shares code with the write flow — 2026-11-14

**Decision:** `lint::check_candidate` runs the checks on the bytes that a write will commit. Write tools and `sync` call it. `lint::run` runs them on the stored documents. Both use the same rule code.

**Alternatives considered:** Separate checks in each write tool (rejected: they would drift).

**Reason:** One code path makes the answer of `lint` and of a write the same. Decided autonomously.

## What an index file is — 2026-11-14

**Decision:** An index file is a normal document, `<folder>/index.md`, with the tag `index` and a marker line `<!-- generated by waymark index -->`. It lists subfolders and the documents of its folder with relative links. It is written for every folder in scope. Nobody edits it by hand. An `index.md` without the tag `index` is a normal document and is never overwritten. An unchanged index is not touched.

**Alternatives considered:**
- A file that is not a document (rejected: Obsidian users would see a file without properties, and `lint` would need a special case).
- An index per top-level domain only (rejected: the folder tree is the organization's choice, so a rule per folder fits all trees).
- Update every index at each write (rejected: it creates merge conflicts, which the original decision wanted to avoid).

**Reason:** A normal document works in Obsidian and under the same checks. The tag and marker make it safe to find. Answers "per domain and per team": the folders are the domains and teams. Decided autonomously.

## Index commits use the verb `update` — 2026-11-14

**Decision:** `index` makes one commit with the message `waymark: update "Index of <folder>"` for one folder, or `waymark: update "Indexes"` for several. No new verb.

**Alternatives considered:** A verb `index` (rejected: the verb list of `git-sync` is fixed).

**Reason:** `activity` and `undo` already know `update`. Decided autonomously.

## Index files are hidden from reading tools — 2026-11-14

**Decision:** `search`, `list`, `stats`, backlinks, and `updates` ignore an index file. `show` and `lint` do not.

**Reason:** An index matches nearly every query and links to every document. See `search-and-read`. Decided autonomously.

## Duplicate titles: the older document keeps the title — 2026-11-14

**Decision:** In a group of equal titles, ordered by `created` then `id`, only the later documents get `duplicate-title`.

**Alternatives considered:** A finding on all of them (rejected: a manual edit of the older, good document would be blocked by the new copy).

**Reason:** A pending edit is blocked only if it is the one that creates the clash. Decided autonomously.

## Built-in patterns, no switch — 2026-11-14

**Decision:** The built-in secret and personal-data patterns cannot be turned off. A knowledge base can only add patterns. A placeholder is skipped.

**Alternatives considered:** An allow list now (rejected: no data on false positives yet. It is in `todo.md`).

**Reason:** The first release keeps the guard simple and safe. Decided autonomously.

## Findings never repeat a secret — 2026-11-14

**Decision:** A `secret` finding names the pattern and the line number and never the matched text.

**Reason:** The message goes to the agent and to logs. Repeating a secret would spread it. Decided autonomously.

## Author fields are a warning, domains are an error — 2026-11-14

**Decision:** `author-mismatch` is a warning. `author-not-allowed` is an error, from `people.email_domains` and `people.email_blocklist` of the shared file.

**Reason:** The `people` settings are in `memory-repository` and had no owner. They guard against a wrong or fake author. Decided autonomously.

## Foundation additions and a changed `requires` — 2026-11-14

**Decision:** `requires` is `search-and-read` (not `mcp-server`), because `lint` uses `Store`. `mcp-server` is implied. `gitsync::log` gets `first_authors` and `last_authors`. `Repo::write` step 5 calls `lint::check_candidate`. New dependency: `regex`.

**Reason:** Reported to `git-sync` and `mcp-server`. Decided autonomously.

## Implementation notes — 2026-11-14

**Decided autonomously.**

- **Rule names in the output.** The format module keeps its names (`not-utf8`, `bad-line-ends`, `broken-property-link`). `lint` renames them to the names of this spec: `bad-encoding`, `bad-line-ending`, and `broken-link` (an error in a property). The fixtures and `document-format` are not changed.
- **Duplicate titles compare active documents only,** by the words of the title (lowercase runs of letters and digits), as the write tools do. A deprecated document and its replacement may share a title. This is a small change from "compared without case and extra white space": punctuation no longer counts.
- **`gitsync` does not call `lint`.** The write checks are made by the write tools (`writes::check_document`), which call the shared code in `lint`. The lower layer `gitsync` stays free of document rules. `manual-edits` calls `lint` on the pending files in the same way.
- **Secret scan moved.** `src/writes/secrets.rs` is now `src/lint/secrets.rs`, with the built-in patterns of this spec (also Slack tokens, JSON Web Tokens, and connection strings). A value that holds `example` or `placeholder`, or starts with `$`, `{`, or a backtick is not an assignment. A bad extra pattern is a `setup_problem`, also in write tools.
- **Scan unit.** `lint` scans the whole file and names the file line. Write tools scan the fields that the call sends and name the line inside the field.
- **IBAN and card scan.** A valid IBAN (mod 97) or card number (Luhn) in any line is `personal-data`. A random long number has a 1 in 10 chance to pass Luhn. Accepted for the first release.
- **`path_authors`** reads the whole history once (`git log --reverse --name-status -M`). A file with pending edits or no history is skipped.
- **`commit_change` guard.** `Repo::write` with an empty list of paths commits nothing. This keeps `git add -A` from running without a path.
- **Index title.** `waymark: update "Index"` is not used: a run that writes only the root index has the title "Index". A run that writes several files has "Indexes".
- **Index links to subfolders** appear only for subfolders that are in scope of the call, so that no link points to a missing file.

## Index files stay manual — 2026-11-14

**Decision (decided with the product owner):** `index` is not run automatically. No write tool refreshes index files, and no setting (such as `auto_index`) is added. The tool stays as an optional extra for people who browse a knowledge base in Obsidian or on GitHub.

**Alternatives considered:** Refresh the indexes of the changed folder and its parents in the same commit as every write. Rejected: waymark is mostly agent storage, and its own tools (`list`, `stats`, `search`) ignore index files, so the files would add commits and diff noise with no reader. A stale index is a `lint` warning, not a state to prevent.

**Reason:** The consistency that matters for agents is in the documents and their links, and that is covered by the link rules of `write-documents`. An overview of the folders for agents belongs in a read tool (see the folder tree discussion in `todo.md`).
